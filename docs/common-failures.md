# Common failures and gotchas

One row per failure, added when it happens: what you see, why, and what
fixes it. Newest at the bottom. A row whose cause is gone is deleted in the
task that removes the cause.

| Symptom | Cause | Fix |
|---|---|---|
| `testkube-minio-testkube` in `ImagePullBackOff`: `pull access denied, repository does not exist` for `docker.io/minio/minio` | Docker Hub removed the `minio/minio` repository; Testkube chart 2.9.5 still points at it | `setup-cluster.sh` pins the drop-in fork `pgsty/minio` (`TESTKUBE_MINIO_*`). Testkube's own `kubeshop/testkube-minio` does not work with chart 2.9.5: it crash-loops with `exec: server: not found` |
| A Testkube workflow ends with `get signed URL: ... The specified bucket does not exist` | The Testkube API creates its MinIO bucket only at startup, and MinIO was not running yet | `kubectl -n testkube rollout restart deploy/testkube-api-server` |
| A changed value under `configMap.data` in `charts/*/values/*.yaml` is synced by ArgoCD but the app still uses the old value | The charts have no checksum annotation, so a ConfigMap change does not restart the pods | `kubectl -n osaan-dev rollout restart deploy/<name>-dep` after the sync |
| A Testkube e2e run on a branch still runs the old tests | The TestWorkflows clone `e2e/` from GitHub `dev`, not the working tree | `make cluster-verify` runs copies of both workflows (`*-local`) that carry the working tree's `e2e/` inline instead of cloning `dev` |
| An edit to `manifests/platform/keycloak/keycloak-realm-import.yaml` syncs, but Keycloak keeps the old clients or redirect URIs | The Keycloak operator imports a realm only when it creates it | Recreate the cluster (`make delete-cluster setup-cluster`), or change the live realm in the Keycloak admin console as well |
| The desktop app's browser pane refuses `https://*.local`: `ERR_CERT_AUTHORITY_INVALID` | The gateway certificate is signed by the cluster's self-signed CA, which the Mac does not trust | Drive the UIs with Playwright (`ignoreHTTPSErrors: true`), as `e2e/` does |
| `make verify` passes locally but a Node step fails in CI, e.g. `node --test scripts/`: "Cannot find module .../scripts" | CI and the Dockerfiles run Node 24; a newer local Node accepts things Node 24 does not | Run the step with `npx -y node@24 ...` to reproduce; [iteration 5](tasks/iteration-5.md) moves everything to Node 26 |
| A service crash-loops in k3d, or its `contextLoads` test fails locally: `ConflictingBeanDefinitionException` for two classes of the same name | `mvn package` without `clean` keeps classes that another branch's build left in `target/`, and Spring loads both | Build with `mvn clean`, as `make verify` and `make cluster-verify` do |
| Every `osaan-ui-e2e` test fails with `net::ERR_CONNECTION_REFUSED at https://osaan.local/` while `cluster-smoke` passes | The cluster was built before `setup-cluster.sh` applied the CoreDNS override, so Testkube runners outside the mesh cannot resolve `osaan.local` | `kubectl apply -f manifests/bootstrap/coredns-custom.yaml`, then `kubectl -n kube-system rollout restart deployment/coredns` |
| A service started with `mvn spring-boot:run -Dspring.profiles.active=local` logs `No active profile set` and cannot reach its database | `spring-boot:run` forks a JVM, and the Maven property does not reach it | `mvn spring-boot:run -Dspring-boot.run.profiles=local` |
| A client that verifies TLS rejects the Compose Keycloak on `https://localhost:8443`: certificate has expired | The self-signed `keycloak/certs/cert.pem` expired on 2026-10-28; the UIs' development settings skip verification and the services' `local` profile disables auth | Regenerate the certificate (and its truststore) from `keycloak/certs/openssl.cnf` if verification is needed |
| `cluster-smoke` takes about 2 minutes instead of seconds and reports some hosts flaky with `Test timeout of 20000ms exceeded`, passing on retry | Not found. Seen on 2026-11-28 for a few runs after ArgoCD rollouts, on hosts the change did not touch | Run it again; later runs passed in seconds |
